# 1. \[이론+실습\] JavaScript와 DOM 연결
## 1.1 JavaScript의 역할
### 1.1.1 HTML·CSS·JavaScript의 역할 비교
- HTML은 화면의 구조와 의미를 만든다.
- CSS는 화면의 배치와 시각적 표현을 담당한다.
- JavaScript는 사용자 행동과 데이터 변화에 따라 화면을 변경한다.

## 1.2 문서 객체 모델(Document Object Model, DOM)
### 1.2.1 DOM이 필요한 이유
- 브라우저는 HTML을 JavaScript가 다룰 수 있는 객체 구조로 해석한다.
- JavaScript는 DOM을 통해 제목, 버튼, 입력창, 목록 영역 같은 요소를 찾고 변경한다.
- 선택하려는 HTML 요소가 없거나 선택자가 잘못되면 기능이 동작하지 않는다.
---
### 1.2.2 요소 선택 예시
```javascript
const title = document.querySelector('.page-title');
const searchInput = document.querySelector('#search-input');
const cards = document.querySelectorAll('.content-card');
```
- querySelector는 조건에 맞는 첫 번째 요소를 선택한다.
- querySelectorAll은 조건에 맞는 여러 요소를 선택한다.
- 변수 이름은 화면에서 맡는 역할을 알 수 있게 작성한다.
---
### 1.2.3 DOM 변경 예시
```javascript
const resultText = document.querySelector('#result-text');
resultText.textContent = '검색 결과 8건';
```
- JavaScript는 선택한 요소의 텍스트, 클래스, 속성 등을 변경할 수 있다.
- 화면 변경은 사용자의 행동 또는 데이터 처리 결과와 연결될 때 의미가 있다.
---
## 1.3 개발자 도구(Developer Tools)와 콘솔(Console)
### 1.3.1 콘솔을 사용하는 이유
- 화면에서 기능이 보이지 않아도 JavaScript 내부 값은 콘솔에서 확인할 수 있다.
- 오류 메시지는 문제 위치와 원인을 좁히는 중요한 정보다.
- 오류가 발생했을 때 코드를 무작정 다시 작성하기보다 메시지와 현재 값을 먼저 확인한다.
---
### 1.3.2 확인 순서
- 브라우저에서 개발자 도구를 연다.
- Console 탭을 확인한다.
- 빨간 오류 메시지의 파일명과 줄 번호를 확인한다.
- 변수 값과 선택 결과를 console.log로 확인한다.
- 수정 후 새로 고침해 같은 오류가 다시 발생하는지 확인한다.
---
# 2. \[이론+실습\] 이벤트와 함수
## 2.1 이벤트(Event)
### 2.1.1 이벤트란 무엇인가
- 이벤트는 클릭, 입력, 선택 변경처럼 사용자가 화면에서 발생시키는 행동을 의미한다.
- 웹서비스는 이벤트를 감지하고 필요한 데이터 처리와 화면 변경을 실행한다.
- 버튼을 만들었다고 기능이 생기는 것이 아니라 이벤트와 처리 로직이 연결되어야 한다.
---
### 2.1.2 클릭 이벤트 예시
```javascript
const filterButton = document.querySelector('#filter-button');

filterButton.addEventListener('click', function () {
  console.log('필터 버튼 클릭');
});
```
- addEventListener는 특정 요소에 이벤트가 발생했을 때 실행할 동작을 연결한다.
- 처음에는 콘솔로 이벤트 발생 여부를 확인하고 이후 실제 기능을 연결한다.
---
## 2.2 함수(Function)
### 2.2.1 함수를 사용하는 이유
- 같은 작업을 여러 곳에서 반복하지 않도록 한다.
- 하나의 기능을 작은 단위로 나누면 오류 위치를 찾기 쉽다.
- 함수 이름은 무엇을 하는지 알 수 있게 작성한다.

---
### 2.2.2 입력과 출력 생각하기
- 함수가 무엇을 받아야 하는지 먼저 생각한다.
- 함수 실행 후 어떤 결과가 나와야 하는지 정한다.
- 화면을 바꾸는 함수와 데이터를 계산하는 함수를 가능하면 구분한다.
---
## 2.3 배열(Array)과 객체(Object) 복습
### 2.3.1 객체는 데이터 1건
```javascript
const item = {
  id: 1,
  title: '웹 디자인 기초',
  category: '디자인',
  year: 2026
};
```
- 객체는 한 항목에 필요한 여러 정보를 이름과 값의 쌍으로 묶는다.
- 6주차 JSON 데이터 1건도 같은 구조로 이해할 수 있다.
---
### 2.3.2 배열은 여러 데이터의 목록
```javascript
const items = [
  { id: 1, title: '웹 디자인 기초', category: '디자인' },
  { id: 2, title: 'JavaScript 입문', category: '개발' },
  { id: 3, title: 'UX 리서치', category: '기획' }
];
```
- 배열은 여러 데이터 항목을 순서대로 보관한다.
- 검색·필터·정렬 기능은 대부분 원본 배열을 조건에 따라 처리한 결과 배열을 만든다.

# 3. \[실습\] 공통 프로젝트 A와 팀 프로젝트 적용
## 3.1 공통 프로젝트 A｜기본 상호작용
### 3.1.1 실습 1｜카테고리 버튼 상태 변경
- 카테고리 버튼을 클릭한다.
- 현재 선택된 버튼에 활성 클래스를 추가한다.
- 기존 활성 버튼에서는 클래스를 제거한다.
- 콘솔에 현재 선택 카테고리를 출력한다.
---
### 3.1.2 실습 2｜검색어 읽기
- 검색 입력창의 값을 읽는다.
- 입력 이벤트가 발생할 때 현재 검색어를 확인한다.
- 검색어 앞뒤의 불필요한 공백을 제거한다.
- 아직 실제 필터링은 하지 않고 입력값이 정상적으로 들어오는지 확인한다.
---
### 3.1.3 실습 3｜보이기와 숨기기
- 상세 영역 또는 안내 영역을 기본적으로 숨긴다.
- 버튼을 클릭하면 해당 영역을 표시한다.
- 닫기 버튼을 클릭하면 다시 숨긴다.
- CSS 클래스 변경을 이용해 화면 상태를 제어한다.
---

# 5주차 핵심 정리
- JavaScript는 사용자 행동과 데이터 변화를 화면에 연결한다.
- DOM은 JavaScript가 HTML 요소를 찾고 변경하기 위한 구조다.
- 이벤트는 사용자 행동을 감지하고 함수는 기능을 작은 단위로 나누는 도구다.
- 배열과 객체는 이후 JSON 데이터와 검색·필터 기능의 기본 구조가 된다.
- 기능을 입력 → 처리 → 출력으로 나누면 구현과 디버깅이 쉬워진다.
