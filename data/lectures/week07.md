# 학습목표
- JSON 파일을 불러와 JavaScript 배열과 객체로 처리할 수 있다.
- 반복 렌더링(Rendering)을 이용해 데이터 수에 따라 목록 화면을 동적으로 생성할 수 있다.
- 빈 상태(Empty State)와 기본 오류 상태를 포함한 데이터 기반 화면을 구현할 수 있다.

# 1. \[이론+실습\] JSON 데이터 불러오기
## 1.1 fetch와 데이터 흐름
### 1.1.1 JSON에서 화면까지
- JSON 파일은 브라우저가 그대로 화면에 보여주는 문서가 아니다.
- JavaScript가 JSON 파일을 불러오고 객체와 배열로 변환한 뒤 필요한 데이터를 선택해 HTML 요소를 만든다.
- 기본 흐름은 JSON → fetch → JavaScript 데이터 → 렌더링 → 화면 순서로 이해한다.
---
### 1.1.2 기본 fetch 예시
```javascript
fetch('./data/items.json')
  .then(response => response.json())
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.error(error);
  });
```
- response.json은 JSON 응답을 JavaScript에서 사용할 수 있는 데이터로 변환한다.
- 데이터가 정상적으로 들어오는지 먼저 Console에서 확인한 뒤 화면 출력으로 넘어간다.
- 파일 경로가 잘못되면 데이터를 불러올 수 없으므로 폴더 구조를 함께 확인한다.
---
## 1.2 원본 데이터와 화면 데이터
### 1.2.1 원본 배열을 보존하는 이유
- 이후 검색·필터·정렬에서는 원본 데이터와 현재 결과 데이터를 구분해야 한다.
- 원본 배열을 직접 계속 변경하면 조건 초기화가 어려워질 수 있다.
- JSON에서 읽은 기본 데이터는 가능한 한 원본으로 유지하고 결과 배열을 별도로 만든다.
---
### 1.2.2 데이터 확인 체크리스트
- 배열인지 확인한다.
- 데이터 건수를 확인한다.
- 첫 번째 객체의 필드를 확인한다.
- ID가 존재하는지 확인한다.
- 예상한 자료형과 실제 값이 같은지 확인한다.
---
# 2. \[이론+실습\] 반복 렌더링과 카드 UI
## 2.1 렌더링(Rendering)
### 2.1.1 렌더링의 의미
- 렌더링은 데이터를 사용자가 볼 수 있는 화면 요소로 변환하는 과정이다.
- 데이터가 30건이라면 HTML 카드 30개를 직접 작성하는 대신 JavaScript가 같은 카드 구조를 반복 생성한다.
- 데이터 수가 바뀌어도 HTML을 다시 작성하지 않는 것이 데이터 기반 UI의 장점이다.
---
## 2.2 반복 처리
### 2.2.1 forEach 예시
```javascript
items.forEach(item => {
  console.log(item.title);
});
```
- forEach는 배열의 각 항목을 순서대로 처리할 때 사용할 수 있다.
- 처음에는 제목만 출력하고 이후 카드 전체를 생성하는 방식으로 확장한다.
---
### 2.2.2 카드 렌더링 예시
```javascript
function renderItems(items) {
  const list = document.querySelector('#item-list');
  const resultCount = document.querySelector('#result-count');

  resultCount.textContent = `총 ${items.length}건`;

  if (items.length === 0) {
    list.innerHTML = '<p class="empty-message">표시할 데이터가 없습니다</p>';
    return;
  }

  const cards = items.map(item => `
    <article class="item-card" data-id="${item.id}">
      <img src="${item.image || './images/placeholder.jpg'}" alt="${item.title}">
      <h3>${item.title}</h3>
      <p>${item.category}</p>
    </article>
  `).join('');

  list.innerHTML = cards;
}
```
- 배열을 map으로 카드 HTML 문자열로 변환하고 join으로 합친 뒤 한 번에 화면에 대입한다.
- 결과 건수와 빈 상태를 같은 렌더링 함수에서 함께 처리한다.
- 렌더링 함수는 화면에 보여줄 데이터 배열을 입력으로 받으므로 9주차 검색·필터 결과에도 그대로 재사용할 수 있다.
---
## 2.3 템플릿 리터럴(Template Literal)
### 2.3.1 데이터와 HTML 연결
- 템플릿 리터럴을 사용하면 문자열 안에 데이터 값을 넣어 HTML 구조를 만들 수 있다.
- 화면에 보여줄 정보와 상세화면에서 보여줄 정보를 구분한다.
- 카드에는 판단에 필요한 핵심 정보만 우선 배치한다.
---

# 3. \[실습\] 공통 프로젝트 A 완성 및 팀 프로젝트 적용
## 3.1 공통 프로젝트 A｜JSON 기반 콘텐츠 목록
### 3.1.1 실습 순서
- items.json을 fetch로 불러온다.
- 데이터 건수를 Console에서 확인한다.
- renderItems 함수를 작성한다.
- 제목·카테고리·이미지를 카드에 연결한다.
- 데이터 수와 카드 수가 일치하는지 확인한다.
- JSON 데이터를 수정했을 때 화면도 바뀌는지 확인한다.
---
### 3.1.2 결과 건수 확인
- 2.2.2의 renderItems 함수가 호출될 때 결과 건수도 함께 갱신되는지 확인한다.
- 초기 전체 목록, 검색 결과, 필터 결과, 결과 0건에서 result-count 값이 실제 카드 수와 일치해야 한다.
- 별도의 결과 건수 함수로 분리하고 싶다면 renderItems 호출 직전에 같은 결과 배열의 length를 전달하도록 한다.
---
## 3.2 빈 상태(Empty State)
### 3.2.1 빈 상태가 필요한 이유
- 데이터가 0건일 때 아무것도 보이지 않으면 사용자는 로딩 중인지 오류인지 결과가 없는지 알 수 없다.
- 결과가 없다는 사실과 다음에 할 수 있는 행동을 함께 알려준다.
---
### 3.2.2 빈 상태 예시
- 조건에 맞는 콘텐츠가 없습니다.
- 검색어나 필터 조건을 변경해 보세요
- 모든 조건 초기화 버튼을 제공할 수 있다.
---
### 3.2.3 렌더링 함수에서 빈 상태 처리
- 빈 상태 처리는 2.2.2의 완성된 renderItems 함수에 포함한다.
- 목록 렌더링 코드와 빈 상태 코드를 서로 다른 예제로 중복 작성하지 않고 하나의 함수를 계속 수정해 사용한다.
---
## 3.3 이미지와 데이터 누락 처리
### 3.3.1 이미지 누락
- 이미지가 없을 때 레이아웃이 깨지지 않도록 기본 이미지를 준비할 수 있다.
- alt에는 이미지 파일명이 아니라 콘텐츠를 식별할 수 있는 설명을 작성한다.
---
### 3.3.2 필드 누락
- 필수 필드가 빠졌다면 데이터 오류로 보고 수정한다.
- 선택 필드는 값이 없을 때 화면에 불필요한 빈 문구가 나타나지 않도록 처리한다.
---
## 3.4 팀 프로젝트 목록 화면 구현
### 3.4.1 적용 순서
- 팀 JSON 파일을 fetch로 불러온다.
- 데이터 5\~10건으로 먼저 검증한다.
- 팀 와이어프레임에 맞는 카드 구조를 만든다.
- 검색·필터에 필요한 data-id 또는 식별 정보를 연결한다.
- 결과 건수를 표시한다.
- 데이터 0건 상태를 만든다.
- 모바일 화면에서 카드 배치를 확인한다.
---
### 3.4.2 구현 완료 기준
- HTML에 데이터를 직접 반복 작성하지 않는다.
- JSON 파일의 데이터가 목록에 자동 반영된다.
- 최소 5건 이상의 샘플이 정상 표시된다.
- 각 항목의 ID를 JavaScript에서 확인할 수 있다.
- 결과 0건 화면이 존재한다.
- 렌더링 코드가 함수로 분리되어 있다.
---
## 3.5 심화 트랙 준비
### 3.5.1 데이터 출처를 바꿀 수 있는 구조
- renderItems는 JSON 파일을 직접 알 필요 없이 배열만 전달받도록 만든다.
- 이후 API 결과를 내부 데이터 구조로 변환한 뒤 같은 렌더링 함수를 사용할 수 있다.
- 클라우드 DB 조회 결과도 동일한 원리로 연결할 수 있다.
