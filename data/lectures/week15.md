# 준비물 및 평가환경
- 최종 배포 URL과 GitHub 저장소를 준비한다.
- 발표용 노트북에서 배포 URL이 정상 접속되는지 확인한다.
- JSON 데이터와 이미지 경로가 배포 환경에서 정상인지 확인한다.
- 발표 전 LocalStorage 초기 상태와 시연용 저장 상태를 각각 확인한다.
- 심화 트랙은 API·클라우드 DB 연결이 배포 주소에서도 정상인지 확인한다.
- 네트워크 문제에 대비해 실행 가능한 로컬 프로젝트 파일과 화면 캡처를 함께 준비한다.

	- 팀프로젝트 수행평가는 1\~14주차 누적 산출물과 15주차 최종 결과물·발표를 종합해 평가한다.
</callout>

# 1. 기말고사｜개인 필기시험
## 1.1 평가 범위
- 9주차 검색·필터·정렬
- 10주차 상세보기와 인터랙션
- 11주차 LocalStorage 기초
- 12주차 개인화 기능과 선택형 API·클라우드 DB
- 13주차 프로젝트 통합·테스트·버그 기록
- 14주차 QA·배포·운영 환경
---
## 1.2 평가 방식
- 개인별 주관식 + 객관식 필기시험으로 운영한다.
- 단순 용어 암기보다 기능이 왜 필요한지, 데이터가 어떻게 흐르는지, 코드가 어떤 역할을 하는지 설명할 수 있는지를 확인한다.
- 코드 일부를 보고 오류 원인이나 실행 결과를 판단하는 문항을 포함할 수 있다.
- JSON과 LocalStorage의 역할 차이, 검색·필터·정렬 처리 순서, ID 기반 상세 연결, 배포 후 점검 항목을 설명할 수 있어야 한다.

# 2. 최종 팀프로젝트 발표
## 2.1 발표 흐름
- 프로젝트명과 한 줄 서비스 정의
- 핵심 사용자(Target User)와 사용자 문제(Pain Point)
- 조사에서 발견한 기회 영역과 핵심 가치(Value Proposition)
- 최소 기능 제품(Minimum Viable Product, MVP)과 핵심 기능(Core Feature)
- 데이터 구조와 JSON 기본 데이터 역할
- 대표 사용자 흐름(User Flow) 시연
- 검색·복수 필터·정렬·상세보기 시연
- LocalStorage 개인화 기능 3개 이상 시연
- 도메인 특화 핵심 기능 시연
- 사용자 테스트에서 발견한 문제와 개선 결과
- 실제 배포 URL과 최종 서비스 상태
- 프로젝트 한계와 다음 단계
- 심화 트랙은 API·클라우드 DB를 선택한 이유와 실패 대응 구조를 추가 설명한다.
---
## 2.2 발표 운영 기준
- 팀별 발표는 약 7\~10분을 기준으로 운영한다.
- 질의응답은 팀당 약 3\~5분을 기준으로 운영한다.
- 팀 수와 수업 운영 상황에 따라 발표 시간을 조정할 수 있다.
- 모든 팀원이 발표 또는 시연 과정에서 자신의 담당 영역을 설명한다.
- 발표 자료만 보여주지 않고 실제 배포 서비스를 반드시 시연한다.
---
## 2.3 시연 시 반드시 보여줄 흐름
- 서비스 첫 진입
- JSON 기본 데이터 목록 확인
- 검색 또는 필터를 이용한 결과 축소
- 정렬 결과 확인
- 항목 상세보기
- 개인화 행동 수행
- 개인화 결과 화면 확인
- 새로 고침 후 LocalStorage 상태 유지 확인
- 결과 0건 또는 오류 상태 중 하나 확인
- 배포 URL에서 전체 흐름이 동작하는지 확인

# 4. 최종 제출 항목
- 실제 접속 가능한 배포 URL
- 최종 프로젝트 전체 파일 또는 GitHub 저장소 주소
- 최종 발표자료
- 프로젝트 보고서

- 팀원별 역할과 기여도 정리
- 개인 회고서
- 심화 트랙은 API·DB 구조와 사용한 외부 서비스의 공식 문서 출처를 함께 정리한다.
<callout icon="📌" color="gray_bg">
	- 제출 위치와 파일 형식은 수업에서 지정한 LMS 또는 Notion 제출 위치를 따른다.
	- 배포 URL과 GitHub 저장소는 제출 후에도 교수자가 열어볼 수 있는 상태인지 확인한다.
</callout>

# 5. 최종 발표 전 체크리스트
- [ ] 배포 URL이 정상적으로 열린다.
- [ ] JSON 데이터가 30건 이상 준비되어 있다.
- [ ] 의미 있는 필드가 최소 8개 이상이다.
- [ ] 검색 기능이 정상 동작한다.
- [ ] 동시에 적용 가능한 필터가 2개 이상이다.
- [ ] 정렬 기능이 정상 동작한다.
- [ ] 상세보기의 ID 연결이 정확하다.
- [ ] LocalStorage 개인화 기능이 3개 이상 동작한다.
- [ ] JSON과 LocalStorage를 결합한 화면이 있다.
- [ ] 결과 없음 상태가 있다.
- [ ] 주요 오류 상태가 처리되어 있다.
- [ ] 모바일에서도 대표 사용자 흐름을 완료할 수 있다.
- [ ] 사용자 테스트 결과와 실제 개선 내용을 설명할 수 있다.
- [ ] 도메인 특화 핵심 기능을 시연할 수 있다.
- [ ] 심화 기능이 실패해도 필수 기능이 가능한 범위에서 유지된다.
- [ ] 모든 팀원이 자신의 역할과 구현 내용을 설명할 수 있다.
