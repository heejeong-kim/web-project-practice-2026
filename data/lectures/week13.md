# 1. \[이론+실습\] 프로젝트 기능 통합
## 1.1 통합(Integration)이란 무엇인가
### 1.1.1 기능이 각각 되는 것과 서비스가 되는 것은 다르다.
- 검색 기능만 따로 동작하고 상세보기에서는 검색 결과와 다른 데이터가 보이면 통합되지 않은 상태다.
- 즐겨찾기가 상세화면에서는 바뀌지만 즐겨찾기 목록에는 반영되지 않으면 통합되지 않은 상태다.
- 핵심 사용자 흐름을 처음부터 끝까지 실행했을 때 같은 데이터와 상태가 일관되게 이어져야 한다.
---
### 1.1.2 통합 점검 순서
- 서비스 첫 진입
- JSON 데이터 로딩
- 검색 또는 필터 적용
- 결과 목록 확인
- 상세보기 진입
- 개인화 행동 수행
- 개인화 화면에서 결과 확인
- 새로 고침 후 상태 확인
- 조건 초기화 후 원래 목록 확인
---
## 1.2 데이터 흐름 점검
### 1.2.1 기본 데이터와 사용자 상태
- JSON 원본은 서비스 공통 데이터를 제공한다.
- 검색·필터·정렬은 JSON 데이터를 조건에 따라 가공한다.
- 상세보기는 선택된 ID에 해당하는 원본 데이터를 찾는다.
- LocalStorage는 사용자가 저장한 ID와 개인 상태를 제공한다.
- 최종 화면은 기본 데이터와 사용자 상태를 연결해 만든다.

# 3. \[실습\] 사용자 테스트와 회귀 테스트
## 3.1 사용자 테스트(Usability Test)
### 3.1.1 교차 테스트 운영 방법
- 기본적으로 2개 팀이 한 조가 되어 서로의 프로젝트를 테스트한다.
- 팀 수가 홀수인 경우 한 조만 3개 팀으로 구성해 순환 테스트한다.
- 첫 라운드에서는 A팀이 테스트 진행자, B팀이 사용자 역할을 맡고 다음 라운드에서 역할을 바꾼다.
- 한 라운드는 과업 수행, 관찰 기록, 짧은 사후 질문까지 약 15분을 권장한다.
- 각 팀은 다른 팀 사용자 최소 2명에게 대표 과업 2개 이상을 수행하게 한다.
- 테스트 진행자는 사용법을 설명하지 않고 사용자의 행동, 망설임, 오류, 발화를 기록한다.
- 테스트 종료 후 발견한 문제를 기능 오류와 사용성 문제로 구분한다.
---
### 3.1.2 테스트 목적
- 개발한 팀이 아닌 사람이 서비스를 처음 사용할 때 어디에서 막히는지 확인한다.
- 기능이 동작하는지뿐 아니라 사용자가 기능을 발견하고 이해하는지를 본다.
- 사용자가 망설이거나 잘못 누르는 지점을 관찰한다.
---
### 3.1.3 테스트 과업(Task)
- 기능 이름을 알려주지 않고 사용자가 완료할 목표를 제시한다.
- 예시｜이번 달 안에 마감되는 디자인 분야 공모전을 찾아 관심 목록에 저장해 보세요
- 예시｜관리하기 쉬운 실내 식물을 하나 찾아 상세 정보를 확인해 보세요
- 예시｜초급 난이도의 자격증 중 가장 가까운 시험 일정을 찾아보세요
---
## 3.2 관찰할 내용
### 3.2.1 행동 관찰
- 첫 행동을 어디에서 시작하는가
- 검색과 필터를 쉽게 찾는가
- 선택된 조건을 이해하는가
- 상세보기로 자연스럽게 이동하는가
- 개인화 행동의 결과를 이해하는가
- 되돌아갈 방법을 찾을 수 있는가
---
### 3.2.2 질문은 테스트 후에
- 테스트 중에는 사용법을 설명하지 않는다.
- 사용자가 요청한 경우에도 가능한 한 먼저 스스로 탐색하도록 한다.
- 테스트가 끝난 뒤 어려웠던 부분과 좋았던 부분을 질문한다.
---
## 3.3 팀 간 교차 테스트
### 3.3.1 진행 방법
- 다른 팀 프로젝트를 처음 사용하는 사용자 역할을 한다.
- 상대 팀이 준비한 핵심 과업 2개를 수행한다.
- 수행 중 막힌 지점과 예상과 달랐던 부분을 기록한다.
- 완료 후 의견과 실제 관찰 사실을 구분해 전달한다.
---

## 3.4 회귀 테스트(Regression Test)
### 3.4.1 수정 후 반드시 다시 확인하기
- 하나의 오류를 수정하면 기존에 잘 되던 기능이 영향을 받을 수 있다.
- 수정한 기능만 다시 보는 것이 아니라 대표 사용자 흐름 전체를 다시 실행한다.
- 같은 데이터를 사용하는 다른 화면도 함께 확인한다.
---
### 3.4.2 최소 회귀 테스트 범위
- 데이터 로딩
- 검색·필터·정렬
- 상세보기
- 즐겨찾기 또는 핵심 개인화
- 새로 고침 후 상태
- 모바일 화면
---
## 3.5 심화 트랙 테스트
### 3.5.1 API 팀
- 정상 응답
- 로딩 중
- 결과 0건
- 네트워크 실패
- API 호출 실패
- 외부 데이터 구조 변경 가능성 확인
---
### 3.5.2 클라우드 DB 팀
- 조회
- 추가 또는 수정
- 다른 브라우저에서 동일 데이터 확인
- 권한 없는 행동 확인
- 데이터 없음
- 네트워크 실패
---
# 13주차 핵심 정리
- 통합은 여러 기능이 같은 데이터와 상태를 기준으로 하나의 사용자 흐름에서 일관되게 동작하는 것이다.
- 테스트 케이스는 정상 상황뿐 아니라 경계와 오류 상황을 포함해야 한다.
- 버그는 재현 가능한 절차로 기록해야 수정 여부를 확인할 수 있다.
- 사용자 테스트에서는 설명보다 관찰이 중요하다.
- 수정 후에는 회귀 테스트로 기존 기능이 깨지지 않았는지 다시 확인한다.
