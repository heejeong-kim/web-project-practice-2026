# 1. 서비스 역분석 방법
## 1.1 서비스 역분석의 개념
### 1.1.1 역분석이란 무엇인가
서비스 역분석은 이미 완성된 웹서비스를 관찰하고, 화면 뒤에 숨어 있는 사용자 문제·서비스 목적·핵심 기능·데이터 구조·사용자 흐름을 거꾸로 추론하는 활동
단순히 화면이 예쁜지, 기능이 많은지를 평가하는 것이 아니라 왜 이 정보가 먼저 보이는지, 왜 이 기능이 필요한지, 사용자는 어떤 순서로 행동하도록 설계되어 있는지를 해석하는 과정으로 이해할 수 있음

### 1.1.3 역분석이 필요한 이유
처음부터 완전히 새로운 서비스를 떠올리기보다 기존 서비스가 문제를 어떻게 해결하고 있는지 관찰하면 반복되는 문제 해결 패턴과 사용자의 기본 기대를 빠르게 이해
여러 서비스에서 공통으로 나타나는 기능은 사용자가 이미 익숙하게 기대하는 기본 기능일 가능성이 높을 수 있고, 반대로 특정 서비스에만 존재하는 기능은 특정 사용자나 상황을 위한 차별화 요소가 될 수 있음
역분석을 통해 파악된 불편이 반복된다면 충분히 해결되지 않은 사용자 문제가 남아 있다는 의미일 수 있음

### 1.1.4 역분석에서 중요한 판단
역분석의 목적은 기존 서비스를 그대로 복제하는 것이 아니라 해결 방식을 관찰한 뒤 무엇이 효과적이었는지, 어떤 한계가 있었는지, 다른 사용자에게 적용한다면 무엇을 바꿔야 하는지를 판단하는 과정이 중요
**관찰 → 사용자 문제 추정 → 기능의 역할 해석 → 한계 확인 → 프로젝트 적용 여부 판단**
> <span color="gray">예시) 기존 서비스에 즐겨찾기 기능이 있다고 해서 그대로 프로젝트에 넣는 것이 아니라 사용자가 여러 항목을 비교한 뒤 다시 확인할 필요가 있는 서비스인지 먼저 판단하고 반복 방문과 재확인이 중요한 프로젝트라면 LocalStorage 기반 즐겨찾기가 의미 있는 기능이 될 수 있음</span>
---

<td>구분</td>
<td>작성 예시</td>
<td>판단</td>
</tr>
<tr>
<td>Pain Point</td>
<td>정보가 너무 많아 원하는 프로그램을 빠르게 찾기 어려움</td>
<td>현재 겪는 문제</td>
</tr>
<tr>
<td>Needs</td>
<td>나에게 해당되는 프로그램만 빠르게 좁혀보고 싶음</td>
<td>필요한 상태</td>
</tr>
<tr>
<td>Feature</td>
<td>대상·분야·일정 필터</td>

</tr>
</table>
- 문제 분석은 기능을 먼저 정한 뒤 이유를 붙이는 방식이 아니라 **Pain Point → Needs → Feature** 순서로 연결
- “검색 기능이 필요함”은 문제 정의가 아니라 해결 방법이므로 사용자의 상황과 어려움을 먼저 서술해야 함

### 1.2.3  핵심 가치(Value Proposition)
핵심 가치는 사용자가 이 서비스를 선택했을 때 얻는 가장 중요한 결과를 한 문장으로 표현한 것을 말하고 기능 이름을 나열하기보다 사용자의 변화와 이점을 중심으로 작성

<tr>
<td>필터 기능 제공</td>
<td>나에게 해당되는 프로그램만 빠르게 좁혀볼 수 있음</td>

<tr>

<td>관심 있는 항목을 다시 검색하지 않고 모아볼 수 있음</td>
</tr>
<tr>

</tr>

- 빠르게 찾기, 비교하기, 기록하기, 맞춤형으로 보기, 신뢰할 수 있는 정보를 얻기처럼 사용자가 얻는 결과를 중심으로 정리

### 1.2.5 데이터(Data / Data Entity / Attribute)
서비스 화면에 반복해서 나타나는 정보는 화면을 구성하는 데이터 후보로 볼 수 있음
카드·목록·상세화면에서 같은 기준으로 반복되는 제목, 분야, 대상, 일정, 장소, 설명, 이미지 같은 값은 JSON으로 관리할 기본 데이터가 될 수 있고, 사용자의 행동에 따라 달라지는 즐겨찾기 여부·최근 본 항목·개인 메모는 사용자 상태 데이터로 구분할 수 있음

### 1.2.6 정보구조(Information Architecture, IA)
정보구조는 사용자가 원하는 정보에 도달할 수 있도록 콘텐츠와 기능을 어떤 기준으로 묶고 연결했는지를 살펴보는 것으로 메뉴 이름 자체보다 카테고리·검색·필터·추천 영역·목록·상세화면이 어떤 관계로 연결되는지, 중요한 정보가 어느 단계에서 제공되는지를 확인하는 것이 중요

정보구조를 분석할 때는 화면 개수를 세는 것보다 사용자가 필요한 정보를 찾기 위해 얼마나 자연스럽게 이동할 수 있는지와 핵심 정보가 적절한 위치에 배치되어 있는지를 중심으로 판단

### 1.2.7 사용자 흐름(User Flow)
사용자 흐름은 사용자가 서비스에 들어온 순간부터 하나의 목표를 완료할 때까지 어떤 판단과 행동을 거치는지를 순서대로 정리한 것으로 단순히 ‘메인 → 목록 → 상세’처럼 화면 이동만 기록하기보다 사용자가 왜 다음 행동을 선택했고 어떤 정보로 판단했는지가 드러나야 실제 서비스 구조를 이해할 수 있음

# 2. 시장 트랜드 분석
## 2.1 이번 수업에서 말하는 시장 분석
시장 분석은 기업 가치나 매출 규모를 계산하는 활동보다 사용자가 어떤 문제를 반복해서 겪고, 현재 어떤 방법으로 해결하고 있으며, 여러 서비스에서 어떤 기능과 정보가 반복되는지를 확인하는 과정으로 보는 것으로, 프로젝트 규모가 작기 때문에 거대한 산업 전체보다 우리가 실제로 다룰 수 있는 사용자와 사용 상황을 중심으로 조사하는 것이 중요
