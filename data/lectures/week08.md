# 중간고사 운영
## 평가 범위
- 1\~7주차 강의 내용에서 출제한다.
- 웹페이지와 웹서비스의 차이, 서비스 역분석, 사용자 분석, MVP·IA·User Flow, JavaScript 기초, JSON 데이터 설계, JSON 기반 렌더링을 포함한다.
- 주관식과 객관식을 함께 사용해 개념 이해와 적용 능력을 확인한다.
## 응시 기준
- 개인별로 응시한다.
- 팀프로젝트 결과와 별개로 개인 학습 성취를 평가한다.
- 코드 전체를 암기하기보다 코드의 목적, 데이터 흐름, 오류 원인을 이해하는지를 확인한다.

# 팀 프로젝트 중간평가
## 발표 준비
- 프로젝트 문제 정의와 서비스 가치 제안을 다시 점검한다.
- 경쟁서비스 분석과 페르소나가 핵심 기능 선정에 어떻게 연결되었는지 정리한다.
- 사이트맵과 User Flow의 변경 사항을 반영한다.
- JSON 데이터 명세와 목록 화면을 최종 점검한다.
- 구현되지 않은 기능은 현재 상태와 후반기 계획을 구분해 설명한다.
## 발표 및 시연
- 프로젝트 문제와 목표 사용자를 설명한다.
- 유사·경쟁 서비스 분석에서 발견한 기회 영역을 설명한다.
- 핵심 페르소나와 주요 Pain Point를 설명한다.
- 사이트맵과 핵심 User Flow를 보여준다.
- JSON 데이터 구조와 주요 필드를 설명한다.
- 구현된 데이터 목록 화면과 기본 상호작용을 데모(Demo)로 시연한다.
- 팀원별 역할과 현재까지의 기여를 산출물 기준으로 설명한다.
## 발표 운영 기준
- 팀별 발표는 약 7\~10분을 기준으로 운영한다.
- 질의응답과 피드백은 팀당 약 3\~5분을 기준으로 운영한다.
- 실제 수강 인원과 팀 수에 따라 발표 시간을 조정할 수 있다.

# 피드백(Feedback) 분석과 후반기 계획
- 교수자와 동료 피드백을 문제 정의, 사용성, 데이터, 기능, 구현 오류로 분류한다.
- 모든 피드백을 반영하지 않고 중요도와 구현 가능성으로 우선순위를 정한다.
- 즉시 수정, 후반기 반영, 보류로 구분한다.
- 9\~12주차의 검색·필터·상세보기·LocalStorage 기능과 연결해 개발 계획을 재구성한다.
- 범위 확대보다 핵심 기능 완성을 우선한다.
<callout icon="📌" color="yellow_bg">
	- 1\~7주차 산출물은 매주 별도로 제출하지 않으며 8주차 중간평가 시 현재 상태를 설명하는 근거 자료로 한 번에 정리한다.
	- 중간평가는 완성품 평가가 아니라 프로젝트의 문제 정의, 설계 근거, 데이터 구조, 현재 구현 수준을 확인하는 체크포인트다.
</callout>
